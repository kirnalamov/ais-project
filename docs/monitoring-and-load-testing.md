## Мониторинг и нагрузочное тестирование

### Метрики и мониторинг

- Backend экспортирует метрики в формате Prometheus по адресу `http://localhost:8000/metrics`.
- В `docker-compose.yml` настроены сервисы:
  - `prometheus` — собирает метрики с `backend:8000/metrics` (конфиг `monitoring/prometheus.yml`);
  - `grafana` — визуализация дашбордов (порт `3000`, логин/пароль: `admin` / `admin`).
- Grafana автоматически подхватывает:
  - источник данных Prometheus (`monitoring/grafana/datasources.yml`);
  - дашборд `Backend Overview (FastAPI)` (`monitoring/grafana/dashboards/backend-overview.json`).

На дашборде отображаются:

- RPS, количество пользователей, доля успешных логинов;
- p95‑латентность;
- запросы по статус‑кодам;
- in‑flight запросы;
- RPS по endpoint’ам;
- пользователи по ролям;
- попытки логина по результату и роли.

### Нагрузочные тесты (`pytest -m load`)

Файл `backend/tests/test_load.py` содержит сценарий `test_increasing_load_until_first_failure`:

- создаёт набор менеджеров, исполнителей, проектов и задач;
- в бесконечном цикле растит:
  - **конкуренцию** (число потоков);
  - **число операций** на фазу;
- внутри воркеров случайно выполняет:
  - логины пользователей;
  - создание новых пользователей, проектов и задач (с зависимостями);
  - отправку сообщений в чаты задач;
  - вызовы анализа графа проекта (`/analysis/projects/{id}/graph`).

Если появляется HTTP 5xx или любое непойманное исключение, тест немедленно падает с сообщением  
о фазе и типе ошибки. Это позволяет:

- запускать длительный стресс‑тест;
- смотреть, как изменяются метрики в Grafana вплоть до момента падения;
- использовать результат как ориентир для оптимизации/тюнинга.

> Важно: не запускать этот тест против продакшн‑среды — только dev/test стенды.
